# ORM 引擎工作原理（nop-orm）

## 1. 摘要（TL;DR）
1. `SessionFactoryImpl` 作为 ORM 的持久化环境实现，集中管理 JDBC、分片、缓存、拦截器、查询执行器，并通过 `PersistEnvBuilder` 预构建实体/集合持久化器与 ID 生成器。【F:nop-orm/src/main/java/io/nop/orm/factory/SessionFactoryImpl.java†L70-L453】【F:nop-orm/src/main/java/io/nop/orm/factory/PersistEnvBuilder.java†L39-L160】
2. `OrmModel` 将 `app.orm.xml` 合并后的实体按拓扑顺序组织，提供按名称、下划线命名、表名的索引，并标记是否有租户字段，是所有运行期元数据的根。【F:nop-orm-model/src/main/java/io/nop/orm/model/OrmModel.java†L21-L105】
3. `LoadedOrmModel` 在持久化环境加载时构建 SQL 元信息缓存、实体/集合持久化器映射，并在编译 SQL 时根据 `compiledSql.isUseTenantModel()` 选择 `TenantCachedQueryPlan` 或 `SimpleCachedQueryPlan`，让查询计划按 `ContextProvider.currentTenantId()` 逐租户缓存并重用，为 `OrmSession` 提供编译入口。【F:nop-orm/src/main/java/io/nop/orm/factory/LoadedOrmModel.java†L84-L111】【F:nop-orm/src/main/java/io/nop/orm/factory/TenantCachedQueryPlan.java†L10-L30】
4. `OrmTemplateImpl` 是应用最常使用的门面，统一封装 session 生命周期、缓存清理、SQL 执行、实体增删改查、批量操作及同步/异步运行。【F:nop-orm/src/main/java/io/nop/orm/impl/OrmTemplateImpl.java†L52-L395】
5. `OrmSessionImpl` 维护实体状态机、批量队列、级联刷新与上下文约束，是真正驱动 `OrmEntityState` 变化的执行体，并在构造时拉起租户感知的缓存实现。【F:nop-orm/src/main/java/io/nop/orm/session/OrmSessionImpl.java†L93-L205】
6. `OrmEntityDao` / `OrmDaoProvider` 把 ORM 元数据映射为领域 DAO，处理 ID 类型转换、批量装载、状态校验，确保调用者按照模型约束访问实体。【F:nop-orm/src/main/java/io/nop/orm/dao/OrmEntityDao.java†L60-L356】【F:nop-orm/src/main/java/io/nop/orm/dao/OrmDaoProvider.java†L24-L76】
7. `OrmConfigs` 揭示了运行期检查必填、查询计划缓存、全局缓存、Schema 初始化、Session 上下文约束等开关，并通过 `nop.orm.sys-user-name` 提供缺省审计用户名，是调优与诊断的配置底线。【F:nop-orm/src/main/java/io/nop/orm/OrmConfigs.java†L21-L88】
8. IoC 自动装配通过 `nop-orm.beans` 引入 `orm-defaults.beans.xml`，`OrmSessionFactoryBean` 收集拦截器/监听器并在 `@PostConstruct` 中为 `SessionFactoryImpl` 注入 JDBC、缓存、模型持有者，依赖 `nop-dao`/`nop-quarkus` 提供的数据源与模板实现。【F:nop-orm/src/main/resources/_vfs/nop/autoconfig/nop-orm.beans†L1-L1】【F:nop-orm/src/main/resources/_vfs/nop/orm/beans/orm-defaults.beans.xml†L13-L92】【F:nop-orm/src/main/java/io/nop/orm/factory/OrmSessionFactoryBean.java†L69-L128】【F:nop-dao/src/main/resources/_vfs/nop/dao/beans/dao-defaults.beans.xml†L14-L102】【F:nop-quarkus/nop-quarkus-web-starter/src/main/resources/_vfs/nop/quarkus/beans/quarkus-defaults.beans.xml†L10-L36】
9. `OrmSessionImpl` 根据 `stateless` 标记与模型是否启用租户自动选择缓存实现：无状态 session 使用 `StatelessOrmSessionEntityCache` 仅维护实体的 attach/detach，普通 session 则在有租户字段时启用 `TenantOrmSessionEntityCache` 校验上下文中的租户编号，否则退化为本地一级缓存。【F:nop-orm/src/main/java/io/nop/orm/session/OrmSessionImpl.java†L131-L149】【F:nop-orm/src/main/java/io/nop/orm/session/StatelessOrmSessionEntityCache.java†L17-L47】【F:nop-orm/src/main/java/io/nop/orm/session/TenantOrmSessionEntityCache.java†L26-L110】
10. `SessionFactoryImpl.getQueryExecutor` 会按查询空间（querySpace）归一化后在 `queryExecutors` Map 中查找 `IQueryExecutor`，缺省回落到 `JdbcQueryExecutor`，后者在执行前编译 EQL、通知 DAO 监听器并通过 `GenSqlTransformer` 补齐分片、租户与数据权限，再由 `IJdbcTemplate` 运行 SQL；但 `OrmSessionFactoryBean.init()` 并未调用 `setQueryExecutors`，因此通过 `<property name="queryExecutors">` 注入的 Map 不会传递到 `SessionFactoryImpl`，自定义执行器默认失效。【F:nop-orm/src/main/java/io/nop/orm/factory/SessionFactoryImpl.java†L287-L376】【F:nop-orm/src/main/java/io/nop/orm/factory/SessionFactoryConfig.java†L137-L149】【F:nop-orm/src/main/java/io/nop/orm/session/OrmSessionImpl.java†L1406-L1432】【F:nop-orm/src/main/java/io/nop/orm/loader/JdbcQueryExecutor.java†L46-L118】【F:nop-orm/src/main/java/io/nop/orm/factory/OrmSessionFactoryBean.java†L69-L128】
11. 多列主键会在模型初始化时被 `OrmCompositePKModel` 封装为实体的 `idProp`，运行期 `OrmCompositePk` 与 `OrmEntityHelper.castId` 会校验段数、空值与类型，保证组合主键调用者必须提供完整的值集合。【F:nop-orm-model/src/main/java/io/nop/orm/model/init/OrmEntityModelInitializer.java†L260-L277】【F:nop-orm/src/main/java/io/nop/orm/support/OrmCompositePk.java†L44-L215】【F:nop-orm/src/main/java/io/nop/orm/support/OrmEntityHelper.java†L154-L190】
12. `IEntityModel.getColumnByTag` 顺序遍历列并返回首个匹配的标签列，后续重复标签会被忽略，因此诸如 `disp`、`parent` 的标签需保持唯一以免引用错位。【F:nop-orm-model/src/main/java/io/nop/orm/model/IEntityModel.java†L128-L171】

## 3. 事实（Facts）
- `OrmModel.init()` 通过 `OrmModelInitializer` 构造拓扑序、表名索引、集合映射，并标记是否存在租户字段，为后续租户会话缓存选择提供依据。【F:nop-orm-model/src/main/java/io/nop/orm/model/OrmModel.java†L21-L105】
- `PersistEnvBuilder.build()` 先构建实体持久化器再构建集合持久化器，并校验实体属性 ID、短名冲突；每个实体都会实例化一次 `IOrmEntity` 验证属性顺序。【F:nop-orm/src/main/java/io/nop/orm/factory/PersistEnvBuilder.java†L58-L160】
- `LoadedOrmModel` 保存 `SqlExprMetaCache`、实体/集合持久化器映射，并在编译 SQL 时根据是否启用租户模型选择缓存包装，落盘到查询计划缓存中。【F:nop-orm/src/main/java/io/nop/orm/factory/LoadedOrmModel.java†L27-L117】
- `TenantCachedQueryPlan` 借助 `ContextProvider.currentTenantId()` 为每个租户维护独立的 `LocalCache`，在缓存缺失时触发重新编译并写入当前租户分支，若上下文没有租户编号则退回共享的 `compiledSql` 槽位。【F:nop-orm/src/main/java/io/nop/orm/factory/LoadedOrmModel.java†L90-L111】【F:nop-orm/src/main/java/io/nop/orm/factory/TenantCachedQueryPlan.java†L10-L30】
- `OrmSessionImpl.flush()` 会先校验上下文、脏标记与只读状态，再创建 `CascadeFlusher` 遍历脏实体、处理待删除集合并驱动 `flushSave`/`flushUpdate`/`flushDelete`，`changedDuringFlush` 循环会在 10 次内补刷新增修改并防止无限递归，最后统一冲刷批量动作队列。【F:nop-orm/src/main/java/io/nop/orm/session/OrmSessionImpl.java†L182-L229】【F:nop-orm/src/main/java/io/nop/orm/session/CascadeFlusher.java†L31-L205】
- `SessionFactoryImpl` 聚合 JDBC、查询执行器、全局缓存、拦截器、DAO 监听器，并提供 `openSession`、`compileSql`、`reloadModel` 等统一入口。【F:nop-orm/src/main/java/io/nop/orm/factory/SessionFactoryImpl.java†L70-L453】
- `SessionFactoryImpl` 在构造新 session 时使用 `OrmSessionImpl`，并根据模型是否启用租户决定实体缓存实现，构造时递增 ORM 指标。【F:nop-orm/src/main/java/io/nop/orm/session/OrmSessionImpl.java†L131-L142】
- `StatelessOrmSessionEntityCache` 只在 `isStateless()` 为 true 时生效，返回命中的实体总是 `null` 并仅管理 attach/detach，因此无状态 session 不保留一级缓存数据；而 `TenantOrmSessionEntityCache` 会为每个租户维护独立缓存并在实体缺少租户号时从上下文补齐，若上下文为空则抛出 `ERR_ORM_MISSING_TENANT_ID(_IN_CONTEXT)`。【F:nop-orm/src/main/java/io/nop/orm/session/StatelessOrmSessionEntityCache.java†L17-L47】【F:nop-orm/src/main/java/io/nop/orm/session/TenantOrmSessionEntityCache.java†L26-L110】
- `OrmTemplateImpl` 通过 `OrmSessionRegistry` 管理上下文 session，`runInSession` 自动复用或新建 session 并在结束时 flush/close，所有 CRUD 都委托给 session。【F:nop-orm/src/main/java/io/nop/orm/impl/OrmTemplateImpl.java†L174-L395】
- `OrmSessionImpl.attach` 会在 `isBindToOtherSession` 校验实体增强器未绑定其他 session 后再放入缓存；当 `cascade=true` 且关联已加载时递归附加 to-one/to-many 引用。`detach` 则通过 `FieldSelectionBean` 深度卸载引用并递归处理集合，确保跨 session 复用前显式分离实体，无法分离时抛出 `ERR_ORM_ENTITY_NOT_DETACHED`。【F:nop-orm/src/main/java/io/nop/orm/session/OrmSessionImpl.java†L1325-L1405】【F:nop-orm/src/main/java/io/nop/orm/OrmErrors.java†L328-L329】
- `SessionFactoryImpl.getQueryExecutor` 会先用 `DaoHelper.normalizeQuerySpace` 归一化查询空间，再在 `queryExecutors` Map 中查找执行器，缺省回落到 `defaultQueryExecutor`；`OrmSessionImpl.executeUpdate/Query/Statement` 都通过该接口获取执行器，而默认的 `JdbcQueryExecutor` 会重新编译 EQL、触发 DAO 监听器、调用 `GenSqlTransformer` 注入分片/租户/过滤信息后才委托 `IJdbcTemplate` 执行。【F:nop-orm/src/main/java/io/nop/orm/factory/SessionFactoryImpl.java†L367-L376】【F:nop-orm/src/main/java/io/nop/orm/factory/SessionFactoryConfig.java†L137-L149】【F:nop-orm/src/main/java/io/nop/orm/session/OrmSessionImpl.java†L1406-L1432】【F:nop-orm/src/main/java/io/nop/orm/loader/JdbcQueryExecutor.java†L46-L118】
- `OrmSessionFactoryBean.init()` 会把 JDBC、BeanProvider、分片、缓存、动态实体等依赖写入新的 `SessionFactoryImpl`，但缺少 `setQueryExecutors` 调用，因此 IoC 层通过 `<property name="queryExecutors">` 注入的 Map 停留在 Bean 配置上，`SessionFactoryImpl` 内部的 `queryExecutors` 仍保持默认空 Map。【F:nop-orm/src/main/java/io/nop/orm/factory/OrmSessionFactoryBean.java†L69-L128】【F:nop-orm/src/main/java/io/nop/orm/factory/SessionFactoryImpl.java†L287-L376】【F:nop-orm/src/main/java/io/nop/orm/factory/SessionFactoryConfig.java†L137-L149】

- 默认 Bean 为 `nopOrmSessionFactory` 设置 `name="app-orm"` 并注入带有 `ioc:config-prefix="nop.orm.global-cache"` 的 `CacheConfig`，`SessionFactoryConfig.buildFullName()` 会据此把查询计划缓存与全局缓存命名为 `orm-query-plan-cache.app-orm`、`orm-global-cache.app-orm`，而 `OrmSessionFactoryCacheManagement.getName()` 也返回 `<name>-session-factory-cache`，让全局缓存注册表与 Micrometer 指标按名称区分多个实例。【F:nop-orm/src/main/resources/_vfs/nop/orm/beans/orm-defaults.beans.xml†L19-L33】【F:nop-orm/src/main/java/io/nop/orm/factory/SessionFactoryConfig.java†L147-L177】【F:nop-orm/src/main/java/io/nop/orm/factory/OrmSessionFactoryBean.java†L94-L156】
- `DefaultOrmModelHolder` 默认加载不含租户层的 `OrmModel` 并缓存单个 `LoadedOrmModel`，`clearCacheForTenant` 仅调用 `clearCache()` 重建全量模型与拦截器缓存，无法区分租户粒度刷新。【F:nop-orm/src/main/java/io/nop/orm/factory/DefaultOrmModelHolder.java†L13-L48】

- `EntityPersisterImpl.init()` 会根据实体模型开启全局缓存与租户缓存，创建持久化驱动与构造器，并在 `queueSave`/`queueUpdate`/`queueDelete` 中串联时间戳、默认值、租户校验、乐观锁、全局缓存驱逐与批量队列，保证实体写入逻辑和缓存一致性；批量加载时若启用全局缓存则强制装载全部属性并在回调中回写缓存。【F:nop-orm/src/main/java/io/nop/orm/persister/EntityPersisterImpl.java†L88-L200】【F:nop-orm/src/main/java/io/nop/orm/persister/EntityPersisterImpl.java†L379-L520】【F:nop-orm/src/main/java/io/nop/orm/persister/EntityPersisterImpl.java†L522-L619】
